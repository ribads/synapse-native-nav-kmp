# SynapseNativeNav

The iOS 26 Liquid Glass navigation shell for [Synapse](https://ribads.com), a set of Kotlin Multiplatform libraries for Android and iOS. It's a native `TabView` with one `NavigationStack` per tab: SwiftUI draws the tabs and navigation bars, and Compose draws every screen.

You don't call this package from Swift. Synapse drives it from Kotlin, so your app adds the package and writes no shell code.

The full guide, including how screens declare their bar, is at [Native iOS navigation](https://ribads.com/libraries/navigation/native-ios/).

## Requirements

- The Xcode 26 SDK or later.
- A deployment target of iOS 16 or later. The shell itself needs iOS 26. Below that, Synapse keeps your full-Compose root.
- A Synapse release that ships the `ui-chrome` artifact, the first one published after `0.2.0-alpha11`.
- A static Kotlin framework (`isStatic = true`), which is what Synapse's project template generates.

## Install

In Xcode, choose **File > Add Package Dependencies**, add the URL below, and link the `SynapseNativeNav` library product to your app target.

```text
https://github.com/ribads/synapse-native-nav-kmp
```

Use the dependency rule **Up to Next Minor Version** from `0.0.1`. In a `Package.swift`:

```swift
.package(url: "https://github.com/ribads/synapse-native-nav-kmp", .upToNextMinor(from: "0.0.1"))
```

## Use it

From your app's `iosMain`, let Synapse choose the root. `nativeShellViewController` returns `null` below iOS 26, and only builds your coordinator where the shell can run.

```kotlin
fun MainViewController(): UIViewController =
    nativeShellViewController { createNavCoordinator() }
        ?: ComposeUIViewController { App() }
```

Your SwiftUI entry point stays as it is, hosting `MainViewController()`. A project generated by Synapse's `init-project` script with `--tabs` already has all of this.

## How it fits together

The package knows nothing about Kotlin. A versioned package can't depend on the framework each app builds with Gradle, so the dependency points the other way: Kotlin calls this package through an Objective-C contract.

| Type | Role |
| --- | --- |
| `SNNShell` | Builds the root view controller and receives paths, tab selection, badges and chrome from the host. |
| `SNNHost` | Implemented by the host. Told about the pops the user makes natively, the back chevron and swipe-back. |
| `SNNEntry` | Implemented by the host. One screen: its view controller, and the taps and insets it receives. |
| `SNNTab`, `SNNChrome`, `SNNChromeAction`, `SNNChromeMenuItem` | Value objects describing tabs and each screen's navigation bar. |

The host owns each tab's path and publishes it whole. SwiftUI assigns it to the `NavigationStack` and reports its own pops back, so the two stay in step.

## Troubleshooting

**`Undefined symbol: _OBJC_CLASS_$_SNNShell`.** The app reaches the shell but doesn't link this package. Add the `SynapseNativeNav` library product to the app target. An app that never calls `nativeShellViewController` doesn't need the package, unless it exports `ui-compose-presentation` into its framework or turns off `DEAD_CODE_STRIPPING`.

## Develop

The package targets iOS, so build and test it with `xcodebuild`, not `swift test`:

```sh
xcodebuild test -scheme SynapseNativeNav -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

The Objective-C surface is a public contract, and Synapse binds it through a header mirrored by hand, so renaming a selector fails at link or run time rather than at compile time. `ObjectiveCContractTests` pins every name. When you change one on purpose, update that test and Synapse's header together, and release a new minor version.
